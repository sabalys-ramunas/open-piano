# Contributing to Piano

Thank you for helping. Piano is a free piano learning app for everyone, including children and complete beginners, so the bar for clear words and easy use is high.

## Set up

You need Node.js 20 or newer.

```bash
npm install
npm run dev      # local server with hot reload
npm test         # all tests (the real-audio test takes about a minute)
npx tsc --noEmit # type check only
npm run build    # type check and production build into dist/
```

Before you open a pull request, `npx tsc --noEmit`, `npm test` and `npm run build` must all pass.

## Find your way around

Read [docs/architecture.md](docs/architecture.md) first. It explains how the screens, the shared services (library, store, settings, input, audio) and each area of the app fit together, with the exact interfaces between them.

Want to add or fix a shared lesson rather than code? See [community/CONTRIBUTING.md](community/CONTRIBUTING.md) and the content policy in [community/POLICY.md](community/POLICY.md). Built-in songs are generated by `npm run build-songs` from `scripts/songs-sources.json` and `src/songs/tunes.ts`; edit those, not the files in `public/songs/`.

## Rules

- **Plain, friendly words.** Write for a ten-year-old who has never touched a piano. No jargon in anything a person reads: say "work out the notes", not "transcription".
- **No em dash** (the long dash, U+2014) in anything a person reads: page text, labels, buttons, `aria-label`, `title`, `alt`, `placeholder`, error messages, page titles, console output, docs and this repository's Markdown files. Use a period, a comma, a colon, parentheses or a middle dot instead. Code comments may use it. Check with:

  ```bash
  grep -rn $'\u2014' src index.html docs README.md CONTRIBUTING.md --include='*.ts' --include='*.css' --include='*.html' --include='*.md' | grep -vE ':[0-9]+: *(\*|//|/\*)'
  ```

- **Strict TypeScript**, no `any`. Avoid new runtime dependencies; ask first if you think one is needed.
- **Accessible by default:** real `<button>` and `<label>` elements, everything reachable by keyboard, visible focus, `aria-live` for status messages, and respect for `prefers-reduced-motion` and the app's own "fewer moving effects" setting.
- **Works from phone width to desktop** without sideways scrolling of the page.
- **Use the shared look.** Colours, sizes, spacing, buttons, cards and form controls come from the tokens and classes in `src/style.css`; labels for levels, hands and modes come from `src/app/words.ts`.
- **Clean up.** A screen's cleanup function must remove every listener, timer, animation frame and subscription it added.
- **Treat outside data as untrusted:** lesson files, catalogs and stored values are checked before use.
- **Tests:** add tests for logic you add, named after the area (`tests/<area>-*.test.ts`). Do not weaken a test to make it pass; fix the cause.
